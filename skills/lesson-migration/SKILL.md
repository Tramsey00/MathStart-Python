# Перенос учебного материала

Открой порученную карточку из [реестра](../../docs/tasks/INDEX.md), затем
[стандарт](../../docs/frontend/lesson-migration.md) и относящиеся к изменению
разделы [UI contract](../../docs/ux/shared-ui-contract.md). Старые ТЗ и I02/I03
не являются текущим дизайном. Не устанавливай новую UI-библиотеку ради переноса.

В MS-T001 переносится новый HTML-урок о линейной функции y = kx + b, указанный
в карточке. Квадратичная функция служит визуальным эталоном и источником общих
компонентов; её runtime-интеграция выполнена раньше MS-T006 в рамках MS-T002
по поручению 24.10.2026. Оба урока используют основной React/Content/FastAPI
runtime и общий browser origin. Повторно переносить квадратичный урок не нужно.

Перед работой примени раздел «Действующие решения пользователя»
в стандарте: именно он задаёт актуальные правила состава урока, навигации,
графиков, общей оболочки и URL. Он заменяет противоречащие ему старые указания.
Изображения не получают enlargement controls; на странице не должно быть
горизонтального overflow. Все lesson routes используют общий FastAPI origin.
Публичные коды предметов и их подписи в breadcrumbs: `algebra`, `geometry`,
`statistics`, `math`. Используй общее сопоставление
`site_content/material-subjects.json`, не переименовывай внутренние Content
identity и не подменяй код русским названием предмета. Второму пилоту MS-T001
утверждён `/materials/5-math-12`; регистрация/публикация — при порученном переносе.
Последний пункт breadcrumbs над заголовком выводи обычным текстом без href и
hover-состояния. Для содержания используй один LessonContents и раздел
«Содержание: принятый образец» стандарта. Основа: панель до 650 px, заголовок
22 px, пункты 17 px, просторные строки до 56 px; телефон — 20/16 px.
При коротком viewport сохраняются пункты 17 px. Сначала уплотняются отступы,
а не шрифт. Список занимает место после полного заголовка и ссылки «К темам
раздела» с учётом реального числа секций. Не вводи отдельный плотный вариант
для линейного урока. Все пункты видны без внутренней прокрутки или обрезки;
активный пункт отличается только фоном, номер с точкой выводится один раз.

По inventory карточки прочитай реальные lesson.json/body.html/page.css/page.js
и media. Отдели смысловые блоки от прежней разметки. Сохрани все формулы, ответы,
таблицы, SVG, section ids оставленных учебных блоков и математическое поведение.
Самопроверка — последняя секция материала. Все учебные блоки после неё исключи
независимо от названия и разметки; поиск только «Итогов»/«Мини-итога» недостаточен.
Саму секцию со всеми заданиями, ответами и решениями сохрани целиком.
IDs удалённых prerequisite и всех блоков после самопроверки исключаются с
пофайловой фиксацией решения пользователя. Неизвестный сохраняемый блок разбери,
не пропускай. Не считай старый HTML внутри dangerouslySetInnerHTML новым уроком.

Используй общий LessonPage и блоки; частную интерактивность держи отдельно от
renderer. Код prototype quadratic не является универсальным парсером для всех
тем. До принятого runtime pilot не запускай класс. После cohort не начинай
следующий класс без поручения. Null URL в inventory требует явного назначения.

Для каждой темы заверши данные, React-композицию, Content URL/redirects и lifecycle.
Для класса выполни полноту inventory. Общие автоматические проверки данных и
проверки функций на представителях относятся к отдельно порученной технической
приёмке; не создавай одинаковый тестовый набор для каждого урока и не запускай
его по инициативе агента.
Профили и карта старых тестов: [testing policy](../../docs/frontend/testing-policy.md).
Точные нарушения записывай кратко в карточке/PR, не плодить tracked скриншоты.

Новый auth UI — отдельная задача. Сессии/права/серверная математика не входят
в визуальный перенос. Завершение: точный scope, результаты, ограничения и список
неперенесённого; ноль оставшихся тем обязателен для приёмки целого класса.

Для обычных правок урока используй HMR через `npm --prefix frontend run dev` на
едином 8131. Не запускай release build после каждой CSS/React правки. Dev preview
content.json не публикует Content; новые URLs/темы требуют явного prepare.
Готовый release проверяется отдельно. Команды — docs/local-development.md.

Решение 25.10.2026: перенос и UI-правки выполняются без автоматических тестовых
прогонов. Не запускать полный/«короткий» frontend, typecheck, browser smoke или
source gates без отдельного поручения. Старые acceptance checklists не являются
разрешением на запуск. HMR используется для пользовательского просмотра.
