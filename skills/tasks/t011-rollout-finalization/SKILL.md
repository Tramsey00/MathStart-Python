# MS-T011 — Завершить интеграцию сайта и вывести старые публичные страницы

Зависимость: MS-T009. Входы: объединённые MS-T003–MS-T008 (263 source-complete темы с peer review); общая runtime-приёмка выполняется здесь. MS-T010 не блокирует задачу. Статус — в [реестре](../../../docs/tasks/INDEX.md).
Карточка описывает будущий результат, не выдаёт наличие прототипа за готовность.

## Результат и входы

Довести объединённый сайт после переноса классов до одного действующего публичного runtime. Исходники 263 React-тем уже в main; это не receipt работы общей версии. Оформление staff отложено в T010 и не входит в обязательную приёмку.

Прочитай AGENTS.md, ARCHITECTURE.md, docs/ux/shared-ui-contract.md, docs/frontend/lesson-migration.md, docs/frontend/testing-policy.md и docs/local-development.md. Не восстанавливай историческую очередь.

## Обязательный объём — решение 16.11.2026

1. Сверить действующие routes/build inputs, каталоги и навигацию всех 263 тем в объединённом main. Не выполнять новый перенос или редизайн уроков.
2. Сделать все внутренние переходы прямыми на существующие новые canonical URL: каталог, footer, соседние темы, хлебные крошки, ссылки внутри уроков, sitemap. Сохранить правильные номера тем, query/anchors и учебное содержание. Не изобретать адрес по display order.
3. Составить пофайловую карту потребителей старых публичных страниц, HTML adapters, CSS/JS/media. Удалить заменённые публичные представления только после замены потребителей; не удалять авторские исходники curriculum, медиа, формулы и решения как «legacy мусор».
4. Старые публичные учебные URL после вывода не отдают прежний интерфейс и не перенаправляют на новый: возвращают настоящую 404. Никаких duplicate pages и цепочек legacy redirects. Сверить каждый retired URL с canonical темой. Это решение заменяет прежнюю обязательную совместимость старых учебных URL. Общие технические HTTPS/auth redirects и safe return не отменяются.
5. Подготовить общую доступную страницу 404 в принятой системе (шапка, фон, темы, переход к материалам). Для скрытого staff URL non-staff не раскрывать существование раздела; server permission/owner/API guards сохраняются. Изменения HTTP-контракта оформить addendum, не переписывать frozen bytes.
6. Проверить совместимость принятых главной/каталога/уроков/auth/ЛК, доступность шрифтов/media и работу обычного входа/возврата. Из закрытого T010 допускается отдельно рассмотреть минимальный подтверждённый общий fix safe return; не переносить весь staff/session refactor.
7. Подготовить одну общую версию для ручной приёмки Русланом. Согласовать профиль runtime-проверок перед прогонами; указать actual SHA/tree и неизвестные области.

## Что не входит

Доработка админки T010; новый UI kit; переписывание tests/tooling и создание QA-каскада; provider/deploy; новые уроки и будущий учебный цикл. Действующий защищённый минимальный staff может остаться отдельным приватным интерфейсом. Не удалять его API/данные/guards ради требования «нет старого публичного UI».

## Приёмка и проверки

Все 263 темы доступны по новым canonical URL; внутренние ссылки ведут туда напрямую; выведенные учебные адреса дают 404 без старого UI и redirect. Нет оставшихся публичных legacy consumers; сохранены контент, anchors, media и Identity. Source completeness, peer review, общая ручная приёмка, merge и production учитываются раздельно.

Текущая testing-policy приоритетна. Эта редакция карточки не разрешает tests/typecheck/build/browser automation/smoke/full suites. До отдельного поручения: NOT_RUN_BY_USER_REQUEST. Штатные validators/guards не отключать. Исторические receipts не подтверждают новый candidate. Реорганизация QA отложена отдельно, сохранение security/content assertions обязательно.

## Git и завершение

Сохрани чужой dirty tree, данные и private config. Отдельные Issue, ветка от свежего main и PR без дублей; не работать в main и не выполнять merge/deploy автоматически. В карточке/PR одна актуальная сводка: исходный/итоговый SHA, карта выведенных consumers, actual checks и ограничения. Саморевью не заменяет независимое review. После передачи остановиться.
