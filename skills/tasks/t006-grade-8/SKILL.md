## Объём работы

1. Открыть весь inventory для 8-klass и сверить актуальный Content source. Изменившийся перечень сначала согласовать явно.
2. Выполнять перенос по разделам, используя один стандарт и общие блоки. Новый повторяемый блок добавлять один раз.
3. Назначить ещё null адреса однократно через Content registry, не из display order на каждом build.
4. Сохранить связи с темами ещё не перенесённых классов через общий resolver.
5. Проверить данные всех 66 тем и representative browser scenarios, включая каждый особый график.
6. Удалять заменённые старые assets с пофайловым disposition после проверки потребителей. Частичный раздел не считать классом.
7. Передать полный список migrated/not-migrated; при готовности not-migrated пуст.
Квадратичная функция входит в эти 66 тем. По отдельному поручению пользователя
24.10.2026 её Content/FastAPI-интеграция выполняется раньше, вместе с MS-T002.
Переиспользовать подключённый документ и график; повторный перенос не выполнять.
Отложенные проверки текущего подключения не считать автоматически пройденными.
Сохранить /materials/8-algebra-32 и принятый дизайн; готовые компоненты не писать
заново. График следует общему контракту: x задаётся только slider-ом, без
pointer/hover probe или crosshair, сетка статична и подписи осей остаются внутри.
Проверить публикацию, no-JS материал, гидратацию и навигацию с остальным классом.

## Приёмка

Все 66 тем класса собраны через новый renderer, имеют устойчивые URL/redirects и доступны из каталога; ни одна тема/формула/таблица/ответ/media/anchor не потеряна; каждый уникальный interactive перенесён и проверен, пользователь принял cohort.

Отметь реализацию, проверки, отдельное review и human acceptance раздельно.
Выбирай проверки по области изменения; не ослабляй семантические/API/security
assertions ради нового внешнего вида. Список неисполненных пунктов и ограничения
передай явно. Результат/команды фиксируй кратко в задаче или PR; временные outputs
в var/ либо frontend/.cache/, без новых tracked audit folders и массовых captures.
