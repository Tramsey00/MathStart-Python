## Результат и входы

Все 75 опубликованных тем grade=7-klass в docs/tasks/lesson-inventory.json, по всем перечисленным предметам и разделам. Записи inventory — полный scope, не выборка удобных уроков.

Прочитай [архитектуру](../../../ARCHITECTURE.md), [стандарт переноса](../../../docs/frontend/lesson-migration.md),
[UI contract](../../../docs/ux/shared-ui-contract.md) и [проверки](../../../docs/frontend/testing-policy.md).
Не перечитывай прежние ТЗ/аудиты: они не являются входом этой задачи.

## Объём работы

1. Открыть весь inventory для 7-klass и сверить актуальный Content source. Изменившийся перечень сначала согласовать явно.
2. Выполнять перенос по разделам, используя один стандарт и общие блоки. Новый повторяемый блок добавлять один раз.
3. Назначить ещё null адреса однократно через Content registry, не из display order на каждом build.
4. Сохранить связи с темами ещё не перенесённых классов через общий resolver.
5. Проверить данные всех 75 тем и representative browser scenarios, включая каждый особый график.
6. Удалять заменённые старые assets с пофайловым disposition после проверки потребителей. Частичный раздел не считать классом.
7. Передать полный список migrated/not-migrated; при готовности not-migrated пуст.

Линейный урок из MS-T001 входит в эти 75 тем. Применить текущий стандарт состава,
стабильных curriculum-based URL и общего разделного resolver; его URL
`/materials/7-algebra-8` не пересчитывать по миграционному порядку. Проверить
совместимость и навигацию; принятый перенос не выполнять заново.

## Приёмка

Все 75 тем класса собраны через новый renderer, имеют устойчивые URL/redirects и доступны из каталога; ни одна тема/формула/таблица/ответ/media/anchor не потеряна; каждый уникальный interactive перенесён и проверен, пользователь принял cohort.

Отметь реализацию, проверки, отдельное review и human acceptance раздельно.
Выбирай проверки по области изменения; не ослабляй семантические/API/security
assertions ради нового внешнего вида. Список неисполненных пунктов и ограничения
передай явно. Результат/команды фиксируй кратко в задаче или PR; временные outputs
в var/ либо frontend/.cache/, без новых tracked audit folders и массовых captures.

## Границы

Сохрани чужой dirty tree, учебную математику и пользовательские данные. Не меняй
платформу публикации вне необходимых документированных adapters. Не трогай
protected acceptance DB. Не запускай следующую карточку автоматически. Merge,
production и provider/security решения требуют отдельного поручения человека.
