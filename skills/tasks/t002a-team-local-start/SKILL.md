# MS-T002A — Подготовить воспроизводимый запуск после clone и передать baseline команде

> Решение пользователя 25.10.2026: автоматические прогоны временно выключены.
> Списки тестов ниже — план отдельно назначенной технической приёмки и история,
> а не разрешение запускать QA при реализации. Для обычной UI-правки — HMR и
> результат NOT_RUN_BY_USER_REQUEST. См. docs/frontend/testing-policy.md.

Зависимости: MS-T002. Это третья задача bootstrap после MS-T001 и MS-T002,
а не публичный deploy. Реализация выполняется только по отдельному поручению.

## Результат

Участник клонирует GitHub-репозиторий, устанавливает документированные зависимости
и открывает новую версию у себя. Не нужны файлы владельца из var/, чужие Docker
volumes, абсолютные C:/Projects paths, действующая локальная БД или cookies.
После приёмки baseline находится в main; MS-T003 может выполняться командой.

## Входы

- Принятые MS-T001 и MS-T002, [архитектура](../../../ARCHITECTURE.md).
- [Локальный запуск](../../../docs/local-development.md), frontend/README.md.
- deploy/RELEASE.md и deploy/RECOVERY.md — если для локального FastAPI/Content
  действительно нужен установленный release; production-разрешением они не служат.

## Объём работы

1. Изучить фактическую причину проблем чистого clone: branch/commit, Node/npm,
   assets и tracked source, build inputs, env и недокументированные локальные файлы.
2. Подготовить понятные команды установки и запуска нового основного приложения.
   Существующий dev:design — временный preview до интеграции, не конечная система.
   Для обычной разработки обязателен один browser origin с Vite HMR: сохранение
   React/CSS обновляет страницу без production build. API, private и legacy routes
   идут в FastAPI через same-origin proxy с исходными Host/Origin/cookies.
   Сохранить отдельный режим просмотра собранного сайта без Node runtime.
3. Для локального FastAPI предусмотреть явную и безопасную подготовку собственной
   disposable/dev БД, schema/content/release по текущему протоколу. Никаких DDL,
   пользователей, seed или загрузки чужой БД при обычном API startup.
4. Приватные значения задаются локально по example без реальных секретов. Порты,
   требования Docker/Node/Python, создание/остановка окружения и сохранность данных
   описаны одинаково для участников; Windows команды проверены, ограничения ОС указаны.
5. Проверить именно чистый clone текущего candidate вне существующего checkout,
   без доступа к var/local владельца. Использовать owned disposable ресурсы.
   Проверить главную, материалы, новый линейный урок из MS-T001, asset URLs и FastAPI boundary.
   Также проверить квадратичную функцию, HMR CSS/React, same-origin WebSocket,
   автообновление существующего content.json без публикации в БД, остановку обоих
   процессов одной командой и отсутствие обязательной зависимости от var/ автора.
6. Сохранить краткие воспроизводимые шаги для команды и исправить README.
7. Передать проверенный локальный запуск ветки ui/ux на review и приёмку
   готовности к merge. После отдельного решения пользователя слить bootstrap
   результаты ui/ux → main и опубликовать на GitHub. Повторить запуск из clone
   опубликованного main; передать точный commit и команды. Эта проверка завершает
   приёмку всей MS-T002A. До неё MS-T003 не начинается.

## Приёмка

Другой участник запускает новую версию из чистого clone по инструкции, без чужих
локальных артефактов. Все нужные исходники и example-конфигурации находятся в Git,
секретов в Git нет. Опубликованный main содержит принятый baseline. Issue/ветки/PR
правила следующего этапа документированы. Ошибки установки и ограничения не скрыты.
Это не приёмка публичного production-сайта; внешний сервер/домен не требуются.

## GitHub и ветка

Продолжать ui/ux, без отдельного Issue и без третьей новой ветки. Исключение
действует только для MS-T001, MS-T002, MS-T002A. Merge main — после решения
пользователя. С MS-T003 каждая задача получает отдельные Issue, ветку от
origin/main без codex/ и PR. Не создавать все Issue заранее.

## Частичное поручение 24.10.2026 — удобный dev-режим

Пользователь поручил настроить live development сейчас, с учётом этой карточки.
Это разрешение на данную часть MS-T002A до полной приёмки MS-T002, а не разрешение
на merge, запуск следующего класса или приёмку всей MS-T002A.

Реализация: `scripts/dev_server.py`, frontend `npm run dev`. Browser origin
остаётся `http://127.0.0.1:8131`: Vite обслуживает React/HMR, внутренний FastAPI
слушает loopback 8132 и сохраняет public origin 8131. Private/legacy UI пока
проходят через FastAPI; их HMR рассматривается при реализации MS-T009/MS-T010.
Изменение public React/CSS не требует build/restart. Существующие React
content.json имеют dev-only read projection и browser auto-reload; это не
публикация Content и не изменение БД. Новые URL/темы/relations требуют явной
подготовки Content и перезапуска dev, а готовая версия — обычного release build.

Пока используется уже подготовленный собственный локальный экземпляр. Создание
окружения/БД/env из чистого clone, отдельное review, человеческая приёмка,
решение о merge и повтор clone опубликованного main остаются НЕ завершены.
