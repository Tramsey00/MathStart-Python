## Основной режим и границы

Windows host-dev в обычной папке проекта: Vite/FastAPI на хосте, PostgreSQL в Docker.
Нужны Git, Python 3.12, Node 24/npm 11, работающий Docker Desktop и включённые
длинные пути Windows. Отдельная папка host-check для ежедневной работы не нужна.
У каждого checkout собственные настройки и данные; готовые установки коллег
сохраняются. Не копировать чужие `var/`, credentials, volumes или `.venv`.

Первая подготовка и обновление после pull — по
[инструкции host-dev](../../../docs/local-development-host.md).
Полный Docker Compose — [альтернатива](../../../docs/local-development.md).
После подготовки, из корня своей папки:

```powershell
npm.cmd --prefix frontend run dev:host
# Остановка из второго терминала той же папки:
npm.cmd --prefix frontend run dev:host:stop
```

Общий browser origin `http://127.0.0.1:8131`; внутренний FastAPI — 8132.
React/CSS обновляются через HMR, изменение Python в backend перезапускает FastAPI.
Startup не делает DDL, bootstrap, seed, build или публикацию Content.
Изменения schema и Content требуют своего просмотренного плана и точного SHA256.
UI-only изменения не требуют публикации; новые URL/identity и Content inputs
обрабатываются по инструкции. Stop сохраняет БД и настройки.

Host-dev до запуска БД проверяет принадлежность конфигурации своему checkout.
При ошибке до готовности останавливает только БД, запущенную им самим.
Нельзя обходить owner/lease/fence, повторять неопределённую публикацию вслепую
или удалять данные для исправления установки; порядок диагностики и восстановления
приведён в инструкции. LongPathsEnabled=1 не заменяет recovery существующей операции.
