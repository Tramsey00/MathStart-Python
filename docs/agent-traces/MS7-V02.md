## PostgreSQL exact replay defect and correction — 2026-10-02

### Initial FAIL preserved

User reported the initial Docker PostgreSQL full suite: 71 tests, 7 failures at
strict `assertEqual(first.content, second.content)` with equal JSON values but
different object-key order. Failing cases: all three onboarding modes,
onboarding old response after PATCH, replay beyond minimum retention,

The initial full-suite result is user-reported evidence; targeted reproduction
and all results below are actual agent runs.

### Confirmed root cause and contract

`IdentityReceipt.response = models.JSONField(null=True)` maps to `jsonb` in the
installed Django PostgreSQL backend. `_save_receipt` saves the envelope dict;
register/onboarding return the in-memory dict on first execution, then the
database-loaded dict on replay. `json_response` previously preserved insertion
order. jsonb reordered nested keys, so reserialization changed HTTP body bytes.
SQLite JSON storage preserved insertion order and concealed the defect.

R02A section 7 requires previous persisted HTTP status/body/operation for same
key/digest, after auth/owner/CSRF/schema and before current state checks. It does
not prescribe an insertion order or require a raw-byte receipt field. Initial
and replay responses now recursively sort object keys at the common HTTP
serialization boundary. JSON values, array order, Unicode, status and persisted
request_id remain unchanged; digest/gates/ownership/retention are untouched.
This provides identical bytes without depending on storage key order.

### Minimal fix and regression evidence

Production change: `users/http.py` adds `sort_keys=True` beside existing UTF-8
serialization. No model, migration, service, security or public schema change.
Existing `assertEqual(first.content, second.content)` assertions retained.

`users/tests/test_identity.py` adds three test methods: nested object-order
invariance including UTF-8 text; preserved array order; real register/onboarding
receipt persistence with recursively reordered keys and strict byte/status/meta
replay assertions. The last test forces reordered storage even on SQLite.
Before fix, these three methods gave exit 1 and 3 failures (two API subtests
plus serializer); after fix the same SQLite run gives exit 0, 3 tests PASS.
Thus the defect can no longer hide behind SQLite's preserved object order.

Only follow-up files changed: http.py, test_identity.py, this trace and active
plan. Previous MS7-V02 changes remain in the working tree. No old migration,
accepted/frozen artifact or existing test semantics modified.
