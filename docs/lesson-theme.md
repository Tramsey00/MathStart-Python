# Общий стиль и ресурсы страниц

Эталон оформления — «Свойства степенных функций и их графики 2.0», 10 класс. Все уроки и остальные страницы сайта подключают одну тему `power-v2`. Заголовки, текст, примеры, таблицы, карточки и самопроверка оформляются централизованно. Рядом с уроком хранится только код его особенностей.

Форматы `themed_html` и `component_html` различаются способом сборки материала, а не набором основных стилей. Общая тема действует при любой ширине экрана. Отдельная разработка мобильного интерфейса в этот этап не входила.

## Где менять оформление и поведение

| Файл | Назначение |
| --- | --- |
| `static/mathstart/css/site.css` | Оболочка сайта, навигация, доступность и общие средства просмотра рисунков. |
| `static/mathstart/css/lesson.css` | Основной стиль шапки, заголовков, текста, кнопок, примеров, карточек, заданий и решений. |
| `static/mathstart/css/lesson-math.css` | Дроби, степени, корни, математические блоки, таблицы и общее оформление рисунков. |
| `static/mathstart/css/lesson-components.css` | Дополнительные учебные компоненты: доказательства, алгоритмы, результаты и подписи. |
| `static/mathstart/css/lesson-diagrams.css` | Диаграммы данных, легенды, наборы исходов и схемы рассуждений. |
| `static/mathstart/css/lesson-contents.css` | Содержание урока: карточки, номера, подписи и состояния. |
| `static/mathstart/css/site-pages.css` | Особенности главной страницы и каталога в рамках общей темы. |
| `static/mathstart/css/widgets/function-graphs.css` | Общее оформление интерактивов с блоком `ms-graph-layout`. |

| `static/mathstart/js/lesson-navigation.js` | Плавные переходы к разделам и управление фокусом с учётом reduced motion. |
| `static/mathstart/js/lesson-diagrams.js` | Общий код масштабирования и просмотра схем. |
| `static/mathstart/js/math.js` | Математическая модель степенной функции. |
| `static/mathstart/js/widgets/power-functions.js` | Управление графиком степенной функции и таблицей значений. |
| `curriculum/.../page.css` | Необязательные стили особенностей конкретной темы. |

| `templates/lessons/components/` | Общая разметка содержания, разделов и заданий. |

Несколько общих файлов разделяют задачи внутри одной темы. Они не содержат отдельных вариантов оформления для старых и новых уроков. `lesson-base.css`, `lesson-legacy.css` и исторический каталог CSS-файлов с хешами больше не используются. Прежние встроенные стили из `reader_styles.html` перенесены в `site.css`; сам шаблон удалён.

## Что допустимо в локальном CSS

Общему элементу достаточно его общего класса. Наличие в уроке таблицы, примера, задания или SVG само по себе не требует `page.css`.

- Рамки, отступы, цвета и типографику общих примеров, заголовков, таблиц и заданий меняйте в общем CSS. Нельзя добавлять в `page.css` собственные версии `.ms-example`, `.ms-task`, `.ms-table` или всей `.ms-lesson-page`.
- Карточки используют `ms-card`, сетки карточек — `ms-card-grid`. Для числа колонок есть общие модификаторы от `ms-columns-2` до `ms-columns-6`; обычная сетка имеет две колонки. Смысловые варианты карточек — `ms-card--success` и `ms-card--error`.
- В `page.css` допустимы размеры конкретной схемы, расположение её подписей, особая подсветка математического объекта или компоновка собственного интерактива. Ограничивайте такие правила классом или идентификатором соответствующего блока; они не должны менять все примеры или рисунки урока.
- Если новая особенность повторяется в нескольких уроках, оформите общий компонент или модификатор и подключайте его класс в разметке.

Например, три карточки результатов используют существующие классы без нового CSS:

```html
<div class="ms-card-grid ms-columns-3">
  <article class="ms-card">Первый результат</article>
  <article class="ms-card">Второй результат</article>
  <article class="ms-card ms-card--success">Проверенный результат</article>
</div>
```

Тесты `content/test_shared_styles.py` проверяют локальные стили и отсутствие встроенных или выведенных из использования таблиц стилей. Проверка не заменяет просмотр страницы и осмысленный выбор общего компонента.

Обычному уроку достаточно `body.html` и `lesson.json`. Экспорт не создаёт пустые `page.css` и `page.js`. Если дополнительный ресурс больше не нужен, удалите файл и опубликуйте урок: его прежний код будет убран из опубликованной страницы. Отсутствие `body.html` считается ошибкой.

## HTML и интерактивность

В `body.html` остаются текст, формулы, задания и геометрия SVG: координаты, линии, точки и подписи. Общие цвета и правила оформления рисунков задаются в общих стилях; особенности одного рисунка — в `page.css`. JavaScript темы пишется в `page.js` без тегов `<script>` и выполняется после появления содержимого страницы. Общие интерактивы подключаются отдельно, без копирования их кода в каждую тему.

`content/services/lesson_theme.py` выбирает известные локальные ресурсы по маркеру `data-lesson-theme="power-v2"`. Шаблон страницы подключает одинаковый основной набор CSS для всех уроков. Страницы сайта дополнительно получают `site-pages.css`, а интерактивные графики — соответствующий файл из `css/widgets/`. Маркер `data-lesson-widget="power-functions"` подключает также общий JavaScript степенных функций. Для остальных интерактивных уроков собственная математическая логика остаётся в `page.js`.

Уроки `component_html` собираются из общих компонентов разделов, заданий и содержания. Уроки `themed_html` сохраняют учебную HTML-разметку, а общие классы обеспечивают то же оформление. Ни один из форматов не подключает прежнюю локальную тему.

## Содержание урока

У `themed_html` содержание автоматически строится из `h2` непосредственных учебных разделов. У каждого нового раздела должен быть уникальный `id`, на который ведёт ссылка. Вручную исправлять автоматически собранное содержание не нужно.

У `component_html` подписи содержания берутся из авторского блока с индивидуальными пояснениями. Учебный HTML внутри разделов остаётся в `body.html`; сборщик не исполняет произвольные Django-шаблоны из материала.

## Публикация изменений

Изменения `body.html`, `lesson.json`, `page.css` или `page.js` требуют публикации урока:

```powershell
python manage.py publish_lessons --slug АДРЕС --dry-run
python manage.py publish_lessons --slug АДРЕС
python manage.py check_lesson_sources --slug АДРЕС
```

Общие CSS и JS из `static/mathstart/` не требуют перепубликации уроков. После изменения этих ресурсов выполните `python manage.py collectstatic --noinput`, чтобы обновились обслуживаемые файлы. Изменения шаблонов компонентов требуют повторной публикации использующих их уроков. Результат проверяется на странице сайта, а не открытием `body.html` отдельно.

## Предыдущие этапы и резервные копии

Первоначальная выгрузка уроков, перенос встроенных ресурсов и объединение общего оформления — разные этапы. Архивы исходников и копии SQLite перед изменениями находятся в `var/backups/`. Учебные тексты, SVG и собственная логика интерактивов сохраняются; локальные варианты оформления заменены общими компонентами.

Исторические генераторы `content/lessons/` и команды `adopt_lesson_theme` и `organize_lesson_assets` относятся к прежним этапам переноса. Для обычного редактирования используются `curriculum/`, общие ресурсы `static/mathstart/` и команда `publish_lessons`.

Папка `data/` при объединении оформления не изменялась. Актуальный переносимый экспорт находится в `var/exports/mathstart-content-unified.json.gz`; предыдущий снимок в `data/mathstart_content.json.gz` сохранён для истории. Порядок восстановления описан в [инструкции по редактированию](editing-lessons.md#перенос-проекта).
