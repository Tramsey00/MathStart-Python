# Проверки на текущем этапе переноса

Решение пользователя от 25.10.2026. Имеет приоритет над прежним «коротким»
профилем, таблицами приёмки и перечислениями команд в карточках.

## Сейчас: автоматические прогоны выключены

Для обычных правок UI, CSS, React-компонентов, текстов и Markdown — **0 тестовых
прогонов по умолчанию**. Не запускать по собственной инициативе npm tests,
typecheck, Playwright, check:dev, verify_repo, source/docs/preservation gates,
полный backend либо новый «маленький smoke». Отдельное поручение пользователя
на конкретную проверку разрешает её scope, а не весь связанный набор.
Запрет проверок нельзя обходить словами «быстрый», «targeted», «smoke» или
«на всякий случай». Не создавать новый каскад взамен удалённого.

Рабочий цикл: реализация → HMR → просмотр/приёмка пользователем. Сборка нужна
для отдельно порученной подготовки готовой версии. Dev startup и сборка не
должны вызывать тестовые suites. Доменные валидаторы и штатные integrity guards
публикации остаются частью приложения; их наличие не разрешает отдельный QA.

## Перенос классов MS-T003–MS-T008 — решение 08.11.2026

Задача агента — перенос по принятому стандарту, сверка с исходником и передача
пользователю для ручного просмотра материала и интерактивов. Автоматические
прогоны и новые QA-скрипты не входят в перенос. Не добавлять тесты на каждый урок,
не запускать browser automation, smoke или gates для завершения карточки.
Непроверенное вручную отметить явно; статус проверок — NOT_RUN_BY_USER_REQUEST.
Статическое review и ручная человеческая приёмка сохраняются раздельно.
Штатная подготовка новых Content inputs выполняется по инструкции с планами/guards;
не повторять её или release build после каждой UI-правки. Валидаторы приложения
не отключать. Отдельно порученная в будущем проверка имеет только свой scope.

## Что изменено

- `test:lesson` удалён: он запускал почти весь frontend suite и не был коротким.
- `scripts/verify_lesson.py` удалён: каскад frontend/typecheck/backend/schema/

- Существующие test-файлы сохранены для будущей отдельно назначенной проверки.
  Их не нужно читать или запускать при каждой UI-правке.

## Только по отдельному поручению

Полный frontend entry — `npm --prefix frontend run test:full`.
Typecheck, `check:dev`, browser, backend и release commands также ручные.
Полные entry points сохраняют assertions, fail/skip/timeout rejection и receipts;
их результат нельзя получать подменой тестов пустым PASS.

Возврат автоматизации — отдельное решение пользователя. Для MS-T009 действует
узкое исключение ниже; в MS-T011 пересмотреть scope, не восстанавливать прежний
массовый набор автоматически. Старые списки и отчёты доступны в Git и не дают
разрешения повторять прогоны. Текущая пометка без запуска — NOT_RUN_BY_USER_REQUEST.
Результаты 24.10.2026 остаются историей того candidate и не проверяют новые правки.

## MS-T009 — решение 13.11.2026

При реализации авторизации разрешены профильные проверки регистрации/входа/
выхода, CSRF/owner/privacy, лимитов/concurrency, смены пароля и отзыва сеансов,
подтверждения/recovery с fake mail, одноразовости/expiry токенов, безопасного
возврата и restore/conflict/retry. При изменении БД — PostgreSQL fresh/upgrade.
Переиспользовать профильные tests и дополнить существенные новые сценарии;
до прогонов прочитать verification skill и runtime-инструкцию по применимости.
UI — ручной просмотр в основном host-dev для desktop/mobile, тем и состояний.
Полные suites, автоматический QA уроков, startup tests и live mail этим не разрешены.
Обычный запуск остаётся минимальным; правила MS-T003–MS-T008 не меняются.
Редакция карточки сама по себе не требует этих прогонов. Непроверенные области
отмечать явно; локальная проверка fake mail не подтверждает реальную доставку.
