# Стандарт переноса учебных страниц

25.10.2026. Стандарт MS-T001–MS-T008. Реализация пилота учитывается отдельно от приёмки.
Внешний вид главной, каталога и квадратичной функции принят пользователем.
Эталон компонентов — [UI contract](../ux/shared-ui-contract.md), тема/шрифты —
[theme baseline](../ux/theme-baseline.md). Не выбирать новые направления и UI kits.

## 1. Результат переноса

### Политика проверок от 25.10.2026

Автоматические прогоны временно выключены. Реализация через HMR и визуальная
приёмка пользователем не запускают тесты/typecheck/browser/source gates.
Перечисленные ниже технические checks — будущая приёмка только по отдельному
поручению, а не default для каждой страницы/правки. См. [политику](testing-policy.md).

### Действующие решения пользователя от 24.10.2026

Этот раздел имеет приоритет над более ранними формулировками ниже, включая
исторический receipt пилота. Для каждой мигрируемой страницы:

- Все блоки помещаются в ширину обычных viewport; у страницы и секций нет
  горизонтальной прокрутки. Длинные заголовки переносятся. Исключение для
  широких данных допустимо только внутри таблицы, если оно нужно для чтения.
- Breadcrumbs идут в порядке «Класс > предмет > раздел». Названия разделов и
  заголовки секций материала без цифровых префиксов; в содержании используется единая автоматическая нумерация
  с точкой.
  Последний пункт breadcrumbs над названием урока — обычный текст, без ссылки,
  hover-фона и акцентного состояния. Переход к разделу остаётся отдельной кнопкой.
- Содержание обоих пилотов и следующих уроков использует один `LessonContents`.
  Просторный квадратичный эталон и правила адаптации закреплены в разделе
  «Содержание: принятый образец» ниже. Не делать отдельный компактный вариант
  только потому, что в линейном уроке больше пунктов.
- Заголовок самопроверки — ровно «Самопроверка». Кнопка ответа компактная,
  справа; разделители и интервалы тонкие и компактные, как в принятом
  квадратичном preview.
- Убрать кнопки увеличения схем/изображений и всю связанную с ними функцию из
  общего UI. Иллюстрации и схемы упражнений оформлять неброской рамкой.
- Не включать секцию «Что нужно знать перед темой». После самопроверки не
  включать заключительные recap/outcome секции. Остальную теорию и задания
  сохранять без смысловой потери.
- У графика координата x задаётся только slider x. Нет pointer/hover probe,
  crosshair или выбора точки указателем; статическая координатная сетка остаётся.
  Деления и подписи осей находятся внутри сетки.
- Убрать всю legacy-навигацию внутри страниц. Общая навигация «Предыдущий /
  Следующий раздел» ведёт между разделами того же класса и предмета; внутри
  раздела подпись — тема. У первой темы первого раздела остаётся только
  «Следующая тема», у последней темы последнего раздела — только «Предыдущая
  тема». «Все темы раздела» показывается всегда и открывает текущий раздел.
- Footer — один общий компонент с шестью ссылками «5 класс»–«10 класс», без
  синтетических placeholder-названий.
- Главная, каталог, линейный и квадратичный уроки доступны на одном browser
  origin `http://127.0.0.1:8131`. В разработке Vite обслуживает HMR и проксирует
  внутренний FastAPI; готовую версию отдаёт FastAPI. Не запускать отдельные
  серверы для отдельных уроков. Подключение квадратичной функции выполнено
  раньше MS-T006 по отдельному поручению в MS-T002.

URL решения: линейный урок — восьмой из 36 уроков алгебры 7 класса в существующем
порядке curriculum, canonical `/materials/7-algebra-8`; прежний числовой адрес
`/materials/7-algebra-1` становится прямым permanent redirect 301. Числа
назначаются один раз по полному curriculum класса и предмета, не по порядку
миграции; после назначения остаются стабильными.

Урок собирается React из типизированного документа и общих компонентов в основном
React Router/SSG-приложении. Публикация проходит существующий FastAPI Content
gateway с immutable release. Отдельный Vite preview и обёртка старого body_html
не являются завершённым переносом. Материал читается без JavaScript; React
подключает содержание, самопроверки и интерактивы без второго DOM-дерева.

В MS-T001 переносится новый HTML-урок «Линейная функция y = kx + b. График
линейной функции» (7 класс); точный источник указан в [карточке](../../skills/tasks/t001-lesson-pilot/SKILL.md).
Квадратичная функция — визуальный эталон и источник общих компонентов.
По отдельному поручению 24.10.2026 она подключена к основному Content/FastAPI
раньше MS-T006, вместе с главной и каталогом в MS-T002. Все четыре страницы
используют один origin; MS-T006 переиспользует подключённый урок.

MS-T001 подтверждает формат и гидратацию на новом уроке. Пока другие темы не
перенесены, явный renderer_version выбирает legacy или React. Отсутствие нового
документа у помеченного React урока — ошибка сборки, не скрытый HTML fallback.
В MS-T001 renderer_version добавлен в lesson.json и immutable ContentDelivery.
Значения — legacy и react-v1; отсутствие поля у прежних источников означает legacy.
React-документ lesson-document-v1 передаётся в lesson_document, валидируется при
подготовке и чтении verified release. Поля БД и applied Alembic history не меняются.

## 2. Целевая организация

```text
frontend/src/
  app/layouts/             общий public layout, отдельные private boundaries
  app/routes/              home, materials, lesson; композиция без копий UI
  shared/layout/           SiteHeader, SiteFooter, PublicPageShell
  shared/ui/               кнопки, поля, диалоги, Brand, theme hook
  shared/styles/           theme.css, base.css, fonts и лицензии
  shared/lesson/           LessonPage, блоки, содержание, самопроверки, схемы
  shared/routing/          формат адреса и lookup, без знания локального сервера
  features/materials-search/
  features/lesson-interactives/  предметные графики и их чистая математика
  server/                  build-only преобразование verified release в view
curriculum/<grade>/<subject>/<section>/<topic>/
  lesson.json              identity, метаданные, версия renderer, stable route
  content.json             типизированный учебный документ после переноса
```

Это целевая группировка, а не требование перекладывать уже работающие компоненты.
Текущая общая оболочка — `shared/lesson/lesson-shell.*`, композиция урока —
`shared/lesson/lesson-page.tsx`, блоки — `source-renderer.tsx` того же модуля.
Квадратичный график находится там же, линейный — в `features/lesson-interactives/`;
главная и каталог — в `features/public-pages/`. Основной runtime получает
типизированный документ через Content. `prototypes/home/lesson-source.mjs`
сохраняется как адаптер исходного эталона, не как вход для всех новых уроков.
Не создавать пустые директории или второй комплект UI ради целевой схемы.

## 3. Источник и формат материала

До переноса canonical — lesson.json/body.html/page.css/page.js. После переноса
canonical для новой редакции урока — lesson.json + content.json; опубликованные
immutable releases не переписываются. Content preparation обязан читать новый
формат через validated schema, а не напрямую из working tree в public request.
После приёмки страницы удалить заменённые body.html/page.css/page.js только при
отсутствии текущих потребителей и наличии пофайловой карты переноса. Переходный
режим не допускает два независимо редактируемых текста одной темы.

MS-T001 вводит versioned discriminated union блоков, например paragraph, heading,
formula, list, table, example, note, figure, selfCheck и interactive. Это перечень
семантических категорий, не разрешение придумывать универсальную схему до чтения
реального источника. Inline spans/links/MathML сохраняют математику и доступность.
Не создавать 263 hand-written TSX-файла с одинаковыми шапкой и секциями.

Конвертер строит черновик документа на этапе подготовки. Неизвестный элемент,
атрибут или активный скрипт выдаёт диагностируемое исключение для разбора.
Нельзя молча пропускать блоки или лечить их generic dangerouslySetInnerHTML.
Разрешённый authored SVG/MathML сохраняется специальным проверяемым путём:
контроль активных атрибутов/URL и сохранение текста, геометрии и aria labels.
Не преобразовывать формулы в картинки, не пересчитывать ответы средствами LLM.

## 4. Сборка страницы и компоненты

Единый layout владеет шапкой, подвалом, темой и skip link. LessonPage владеет
заголовком, breadcrumbs, содержанием, article sections и навигацией. Секция имеет
стабильный id, заголовок и блоки. Содержание генерируется из тех же секций.

| Исходный смысл | Компонент/поведение |
| --- | --- |
| Тема, класс, предмет | LessonHeading, данные каталога |
| Заголовки секций | LessonSection; тот же id в содержании |
| Пример | WorkedExample без копирования стилей |
| Правило/примечание | LessonNote, общий variant при необходимости |
| Задание с ответом | SelfCheck; отдельная кнопка справа |
| Раскрываемый ответ | LessonDisclosure; плавное появление, inert при закрытии |
| Таблица | Семантическая table, локальный horizontal scroll |
| Авторская схема | LessonDiagram; сохранение SVG и подписи |
| График | Зарегистрированный React interactive, typed props |
| Предыдущая/следующая тема | LessonNavigation и общий route lookup |

Сначала использовать текущие exports shared/lesson/index.ts. Общий компонент
расширять параметром только при реальном повторном сценарии. Частный график
не помещать в generic renderer через сравнение русского текста или HTML id.
Частные ms-quadratic-* условия source-renderer и адаптер исходного эталона
нельзя размножать по классам. Число секций берётся из текущего документа, а не
из исторического HTML или фиксированной константы. Линейный график использует
собственную математику; общие controls и shell переиспользуются, формула параболы
не переносится. Автоматические математические проверки запускаются только
по отдельному поручению согласно текущей политике.

Порядок и смысл сохраняемой теории, заданий, ответов, таблиц, MathML, SVG и
изображений сверяются с источником. Для состава секций применяются действующие
решения пользователя выше: «Что нужно знать перед темой» и завершающие
recap/outcome после самопроверки исключаются, всё остальное учебное содержание
сохраняется. Числа полного исходного состава не выдаются за новый состав.

## 5. Стиль и поведение

Общая Professional тема light/dark, base и локальные шрифты/OFL подключаются один
раз в layout. Не смешивать старые глобальные site.css с новой системой на
перенесённой странице. Для legacy страниц сохранить их необходимые assets.
Lesson CSS scoped; subject-specific CSS не переопределяет global tokens.
Общая шапка использует белую light-поверхность, подвал — отдельный фон.
Размеры кнопок, нумерация с точкой, отступы и hover — из UI contract.
На UI-кнопках и навигационных ссылках hover не добавляет подчёркивание;
анимация не меняет их согласованные размеры.

### Содержание: принятый образец

Основа — приложенный пользователем 25.10.2026 образец содержания квадратичной
функции. Его реализует общий компонент, включая линейный урок с 11 секциями;
у квадратичного урока сейчас 8 секций. Новые уроки передают данные тому же
компоненту, а не копируют его разметку и CSS.

- Панель слева до 650 px на всю высоту окна, в светлой теме серо-светлый фон,
  справа затемнение. Контент desktop начинается в 110 px от левого края:
  боковая полоса 80 px и отступ 30 px. На телефоне панель занимает ширину окна.
- Сверху отдельная ссылка со стрелкой «К темам раздела», ведущая в текущий
  раздел; ниже полное название урока. Оно переносится без ellipsis, обрезки и
  принудительного `nowrap`. Маленький крестик находится в боковой полосе.
- Desktop: заголовок 22 px, пункты 17 px, номер около 16 px. Номер с точкой
  выводится один раз; колонка номера 18 px, промежуток до текста 10 px.
  При свободном месте высота пункта 56 px и промежуток между пунктами 2 px,
  как на образце. На телефоне: заголовок 20 px, пункты 16 px, промежуток до
  текста 4 px. Это не изменение шрифта основного материала.
- Доступное место списка рассчитывается после ссылки и полного заголовка.
  Список учитывает реальное число секций. Сначала сокращаются вертикальные
  отступы и свободная высота пунктов; короткий список не превращается в плотный
  только из-за общего breakpoint 740 px. При высоте до 620 px пункты остаются
  17 px, уменьшаются межстрочный интервал и отступы, заголовок сохраняет размер.
- У списка нет внутренней вертикальной или горизонтальной прокрутки. Все
  названия и последний пункт остаются видимы. Один `overflow:hidden` не
  считается выполнением требования: запрещено прятать лишние пункты,
  сокращать подписи, исключать секции ради высоты или уменьшать шрифт до 13–14 px.
  Для отдельно назначенной визуальной приёмки ориентиры: 1440×1000, 360×800,
  320×568 и 720×500; автоматические прогоны сейчас выключены.
- Активный пункт отличается только мягким фоном: обычные цвет и насыщенность
  текста и номера, без синего акцента, рамки или подчёркивания. Нажатие ведёт
  к исходному якорю секции и закрывает панель.
- Появление/закрытие плавные; Escape и нажатие по затемнению закрывают панель.
  Сохраняются focus trap/return, блокировка прокрутки подложки, keyboard и
  `prefers-reduced-motion`. Конкретные motion tokens — в UI contract.

Содержание открывается плавно и управляет фокусом. Ответ раскрывается только
своей кнопкой; формулировка задания не становится кнопкой. Текст урока можно
копировать; labels кнопок и график — user-select:none по принятому образцу.
Везде keyboard/focus-visible, Escape и возврат фокуса у диалогов, reduced motion.
Перенос длинного заголовка и таблицы не должен расширять viewport.

График: чистые вычисления отдельно от React; один владелец состояния. Reset
анимирован с отменой при новом вводе. Pointercancel/scroll/swipe не выбирают точку;
Точку x выбирает только keyboard/pointer slider, сам график не реагирует на курсор или tap. Эффекты удаляют listeners/RAF.
Нельзя подключать page.js одновременно с его React-заменой.

## 6. URL, ссылки и поиск

Формат: /materials/<grade>-<subject>-<number>. Квадратичный урок сохраняет
/materials/8-algebra-32. Канонический адрес линейного пилота —
/materials/7-algebra-8; прежний /materials/7-algebra-1 является 301 alias.
Subject — утверждённый Latin code. Начальное назначение номеров выполняется один
раз по полному порядку curriculum внутри класс+предмет; после назначения номер
стабилен и никогда не вычисляется из порядка миграции или текущего display order.
Реестр Content — единственный источник назначения для backend, build и UI.
Назначения находятся в site_content/material-routes.json; Content валидирует
уникальность и соответствие identity/renderer, frontend routing импортирует тот же
реестр. В receipt фиксируются его исходные bytes/digest. Runtime использует только
canonical path и redirects из pinned release, не читает рабочий реестр.

В [inventory](../tasks/lesson-inventory.json) перечислены все опубликованные темы.
null assigned_path означает, что адрес ещё не назначен; не публиковать его как
догадку. MS-T001 утверждает и реализует назначение, cohort добавляет свои записи
однократно до публикации. Коллизия slug/path или неполный mapping — FAIL.

Старые public URLs перенаправляются одним server-side permanent redirect на
canonical path, без цепочек. Query сохраняется; fragment обрабатывается браузером
и проверяется реальным переходом. Прямой URL, reload, Back и якоря работают.
Unpublished/неизвестные страницы дают 404. Каталог не должен ссылаться на localhost.
Навигация идёт между разделами в пределах того же класса и предмета; внутри
раздела — между темами. См. действующие решения пользователя в начале стандарта.
Во время перехода общий resolver поддерживает обе версии страниц.

## Разработка и готовая версия

В задачах переноса обычный UI preview — единый HMR-режим `npm --prefix frontend run dev`
на 8131. Не пересобирать SSG и не перезапускать API после каждого изменения
React/CSS. Существующий content.json имеет dev-only auto-refresh со schema/identity
validation; это не публикация. Новый URL/урок/каталог проходит явный Content prepare
и перезапуск dev. Для передачи готовой версии используется обычная immutable
сборка и FastAPI; результат HMR smoke не доказывает release readiness.

## 7. FastAPI, SSG и авторизация

SSG использует verified immutable input; Node — build-time, не новый runtime SSR.
FastAPI Content gateway и publication authority сохраняются. В MS-T001 проверить
и изменить current public no-hydration/full-document assumptions, meta/canonical,
asset manifests и hydration boundary. Одобрение прототипа не доказывает интеграцию.
Основной текст присутствует в public HTML без JS; поздняя загрузка интерактивов
не создаёт hydration mismatch и не теряет материал. Client navigation допустима
только после разбора lifecycle; обычные ссылки остаются допустимым первым шагом.

Старые I02/I03 UI и demonstration auth fixtures не являются образцом нового UI.
Настоящий account/staff runtime пока сохраняется до MS-T009/MS-T010. В задачах
уроков не менять users DB, sessions, CSRF, permissions и onboarding semantics.
Homepage email/password preview не подключать к username API молча. MS-T009
сначала получает решение email/username и маршрутов, затем заменяет старый UI,
его потребителей и тесты. Не удалять backend Identity под видом CSS cleanup.
Legacy самопроверки не пишут mastery и не становятся Assessment API.

## 8. Последовательность одной темы

1. Прочитать карточку и точную запись inventory; изучить все source assets.
2. Составить список секций, формул, таблиц, ответов, SVG, интерактивов и якорей.
3. Преобразовать в validated document; неподдерживаемые блоки разобрать явно.
4. Подключить общие компоненты и мигрировать нужный интерактив без старого script.
5. Добавить постоянный URL и redirects через Content, проверить соседние ссылки.
6. Сверить смысловую сохранность по исходникам; передать UI для просмотра через HMR. Автоматические checks — только по отдельному поручению.
7. Записать результат страницы в cohort inventory/status, удалить заменённые
   текущие источники только после доказанной эквивалентности и human acceptance.

Одна задача класса завершается только при полном inventory. Агент может делать
промежуточные scoped commits; перенос одного раздела не означает готовность класса.
Найденный общий дефект исправляется в общем компоненте, а не в каждой странице.

## 9. Техническая приёмка — автоматические прогоны отложены

Ниже указан будущий scope, а не разрешение запускать проверки в текущей работе.

Для всех тем cohort: schema validation, полнота текста/формул/ответов/media/anchors,
уникальность URL, redirects, сборка и разрешимость ссылок. Это автоматическая
проверка данных, не 263 копии одинакового screenshot-теста. Каждый уникальный
interactive имеет математические unit tests и реальный interaction scenario.
Общие controls проверяются на представителях тем, mobile/desktop, light/dark,
200% zoom и reduced motion по [политике проверок](testing-policy.md).

Отдельно фиксируются implementation, checks, review, visual acceptance и merge.
Нельзя считать prototype build или старый PASS проверкой нового runtime candidate.

## 11. Историческая запись исходного пилота MS-T001

Этот раздел фиксирует исходное назначение и candidate до пользовательских
корректировок. Текущий URL и требуемое поведение определены в разделе 1; ниже
оставлены только provenance-сведения исходного выполнения.

Линейному уроку явно назначен `/materials/7-algebra-1`. Номер 1 назначен как
постоянный идентификатор, не вычисляется из display order. Старый slug и известные
redirects ведут непосредственно к canonical с сохранением query; fragment
сохраняется браузером. Назначение квадратичного preview 8-algebra-32 сохранено,
его renderer остаётся legacy до MS-T006.

`frontend/scripts/convert-lesson.mjs` преобразует HTML в черновик content.json,
отказывается от неизвестной активной разметки и сохраняет semantic nodes:
paragraph, note, example, selfCheck, table, figure, interactive, inline/structure
nodes. Пилот содержит 13 секций, 13 самопроверок, 4 таблицы, 3 авторских SVG и
один linear interactive. Предварительные знания и экспресс-анализ сохранены.
Полная проверка сравнивает текст каждого раздела, клетки таблиц, SVG и anchors
с замороженным источником. Учебное пояснение под графиком осталось документом.

В переходный период body.html/page.css/page.js пилота сохранены как замороженный
источник сравнения и совместимости publication snapshots; не редактировать их
независимо от content.json. Удаление возможно после human acceptance и проверки
всех потребителей. Для новой React редакции учебный canonical — content.json.

LessonPage собирает общий chrome, содержание и секции. LinearGraph использует
отдельную чистую математику, а CoefficientControl разделяется с QuadraticGraph.
Исходные диапазоны сохранены: k от −3 до 3, b от −6 до 6, шаг 0,5; окно x от −8
до 8, y от −16 до 16. Reset возвращает k=1, b=0, учитывает reduced motion и
отменяется новым вводом. Swipe/pointercancel не выбирают точку.

SSG оставляет Router hydration только для react-v1. Legacy документы сохраняют
прежний renderer и полный document lifecycle. Ссылки урока обычные; переходы
утилизируют listeners/RAF вместе с документом. В initial render нет чтения storage
и времени; сохранённая тема применяется после hydration. Без JS содержание
использует native details, а решения доступны без inert/aria-hidden. CSS нового
урока подключается отдельно от legacy site.css. Сервер проверяет реальную статью,
а не вхождение документа в сериализованный hydration payload.

Статусы реализации, проверок, отдельного review и визуальной приёмки находятся
в карточке MS-T001 и реестре. Этот раздел сам по себе не означает PASS или приёмку.

Дополнение по review пилота: prepare/build проверяет source_path и published
source digest каждого react-v1 документа; неизбранный source нельзя публиковать
только за счёт изменения content.json. Строгая проверка всех nodes/attrs/URLs и
соответствия title/grade/subject/section повторяется при чтении immutable release.
Frozen CSS/JS учитываются compatibility_assets_digest без исполнения в React.
Canonical redirects выводятся только для опубликованных страниц, а quality check
читает pinned release через настоящий UnitOfWork, не текущий live registry.
