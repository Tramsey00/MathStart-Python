## 1. Goal

Создать первое исполняемое ядро MathStart Harness:

- единый CLI;

- TaskManifest v1;

- RunResult v1;

- run lifecycle;

- заменяемый model adapter protocol;

- capability declaration;

- deterministic FakeAdapter;

- fake model/tool loop;

- фиксацию Git state;

- базовые execution limits;

- CLI/unit/smoke tests;

- fixture run и setup guide.

Результатом задачи должна быть одна демонстрируемая команда запуска Harness.

## 2. Inputs

- R01 repository knowledge/workflow;

- R02 exercise/HTTP contracts;

- R03 knowledge/progress contracts;

- MathStart Technical Specification v6.0, section 11;

- repository verification entry point `scripts/verify_repo.py`.

Direct dependency: R03.

## 3. In scope

### Contracts

- TaskManifest v1;

- RunResult v1;

- RunStatus;

- exit-code mapping;

- AdapterProtocol v1;

- AdapterCapabilities v1;

- draft Profile schema;

- draft Hook schema.

### CLI

Implement:

- `python -m harness doctor`

- `python -m harness run <task-id> --mode dry-run`

- `python -m harness run <task-id> --mode execute`

- `python -m harness status <run-id>`

### Runner lifecycle

The runner must:

- load and validate task manifest;

- create a unique run ID;

- capture repository root;

- capture base SHA;

- capture current branch;

- capture initial working-tree diff/state;

- select adapter;

- enforce max-turn and wall-time limits at runner level;

- execute deterministic FakeAdapter loop;

- persist RunResult;

- map final status to documented process exit code;

- handle interruption without reporting success.

### Fake adapter

Implement a deterministic adapter capable of:

- declaring capabilities;

- returning scripted model messages;

- requesting fake/registered tool actions;

- consuming tool results;

- returning FINISHED;

- simulating errors/interruption/turn exhaustion.

## 4. Out of scope

- production Codex adapter;

- a generic agent framework.

These are handled by R05-R08.

## 7. TaskManifest acceptance

Execute must be blocked before model invocation for at least:
- unknown schema version;
- missing task ID;
- invalid/missing base SHA;
- missing required accepted spec;
- accepted-spec digest mismatch;
- invalid repository-relative path;
- path traversal;
- invalid limits;
- unsupported adapter/profile configuration.
Dry-run must:
- validate configuration;
- show planned adapter/profile/checks/limits;
- perform no model invocation;
- perform no network request;
- perform no product-file mutation.
## 8. RunResult statuses and exit codes
External mapping:
- READY_FOR_REVIEW -> exit 0
- FAIL -> exit 1
- BLOCKED_CONFIGURATION -> exit 2
- NEEDS_HUMAN -> exit 3
- INTERRUPTED -> exit 4
- BUDGET_EXCEEDED -> exit 4
READY_FOR_REVIEW does not mean merge, DONE, or human acceptance.
## 9. Required tests
At minimum:
1. valid manifest accepted;
2. unknown schema version blocked;
3. missing accepted spec blocked;
4. invalid/traversal path blocked;
5. dry-run invokes adapter zero times;
6. dry-run does not mutate product files;
7. fake execute produces expected deterministic result/diff;
8. unique run ID cannot be reused;
9. turn limit produces BUDGET_EXCEEDED;
10. interruption produces INTERRUPTED;
11. interrupted run never produces READY_FOR_REVIEW;
12. status reads a persisted result;
13. base SHA and branch are recorded;
14. initial dirty state is distinguishable from run-produced changes.
## 10. Acceptance
R04 is accepted when:
- invalid task/spec/path blocks execute;
- dry-run performs no model/network invocation and no product-file mutation;
- FakeAdapter executes a verifiable deterministic tool loop;
- run result contains task/run/Git/status/limit/verification information;
- interruption and limit exhaustion cannot be reported as success;
- CLI tests and relevant repository verification pass;
- runner skeleton, specs, fixture run, tests and setup guide exist;
- reviewer Vladimir accepts the handoff.
