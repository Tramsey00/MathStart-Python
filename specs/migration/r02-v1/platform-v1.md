# Platform and persistence addendum v1.0.0

PROPOSED. Implements framework-facing interpretation of accepted ADR0006 only.
Domain semantics and root PRODUCT/ARCHITECTURE/Harness remain frozen.

The target is one synchronous Python modular monolith and one PostgreSQL16+
database, SQLAlchemy2 Session per unit of work, Alembic single reviewed chain;
React/TS/Vite/React Router framework pre-render for public routes. Node is a
build tool. Versions/locks are V01/I01 decisions, never floating latest here.
Explicit SQLite supports local non-concurrency work only, never PG fallback or
locking/upgrade acceptance. The current runnable implementation remains Django.

## Complete baseline mapping

[schema-mapping-v1.json](schema-mapping-v1.json) carries every baseline physical
column/constraint/index/applied migration from the sanitized R01 PG inventory,
plus code-level field/relationship/default/on_delete metadata for every model,
including auto-created M2M tables. Each column maps to the identical table and
column name. No renumbering: content/auth integer/bigint IDs and users UUIDs;
preserve all unique/check constraints, FK targets, join IDs and storage keys.
R01's sequences array is empty, so it is NOT evidence of absent sequences.
The separate sequence reflection is taken only from the disposable fresh PG
schema, identifying GENERATED BY DEFAULT AS IDENTITY and owned sequences.
V01 must compare the deployed copy's sequence metadata and values as well.

SQL types: UUID -> native uuid; JSONField -> jsonb with explicit JSON null versus
SQL NULL; DateTimeField -> timestamptz microseconds; PositiveInteger/SmallInteger
-> integer/smallint with >=0 checks; Boolean -> strict bool; Char/Slug/FileField
-> existing varchar length; Text -> text. Auth User/Group/Permission IDs are int4;
content and M2M auto IDs are int8. FileField means a storage key, not inline media.
No automatic path rewrite, escaping, lowercasing or Unicode normalization.

Python/model defaults are application defaults, usually NOT SQL defaults.
auto_now_add assigns UTC at insert; auto_now only on saves that include that
field (update_fields/bulk QuerySet.update behavior must match). Publish increments
updated_at/published_at only on the corresponding accepted write. Preserve
existing instants/precision; never replace them with migration execution time.
uuid4 is generated only for new rows. Blank text defaults to empty string;
nullable grade/mode/receipt fields stay NULL. Grade legacy epoch is
2026-10-04T00:00:00Z, a tracking epoch, not reconstructed historical creation.
Populate missing profiles only; existing selected grade/mode/state is untouched.

Physical Django FKs are generally deferred NO ACTION. Django on_delete is a
collector/service behavior, not a claim of SQL ON DELETE CASCADE. Keep physical
constraint/deferability and implement collector-equivalent target services:
Subject.grade and Section.subject CASCADE; page grade/subject/section SET_NULL;
publication.page CASCADE; media.related_page SET_NULL; profiles.user/grade and
receipt.user PROTECT; auth joins/admin log behavior as mapping. Evaluate all
PROTECT blockers before any deletion. No passive ORM cascade can bypass a
protected user through bulk/delete-selected. Model choices are not DB CHECKs
unless the mapping names an actual constraint; application validation remains.

Preserve PK sequence ownership/type/increment/min/max/cycle/cache and never move
a sequence backwards. After copy, next generated ID must exceed max existing ID;
use reviewed setval semantics respecting is_called/empty-table behavior and any
already-higher last_value. This is V01 rehearsal work, not SQL executed by R02.
Retain django_migrations/admin/session/contenttype history; no DROP required.
Keep permission IDs/codenames/contenttypes and M2M assignments stable, including
users models that have no registered admin. New target sessions/journal/bridge
tables require V01 reviewed additive DDL; R02 does not create them.

## Shared transaction and lock protocol

All new target services acquire only needed locks in this total order:
1 publication activation gate (only publication/catalogue writes);
2 namespace advisory locks sorted by (domain, stable scope), including creation
and unique-key races;
3 existing User rows ascending PK;
4 Group rows, auth membership/direct/group-permission joins ascending PK, then
IdentityReceipt rows by (scope,operation,key_digest);
5 StudentProfile rows ascending user_id;
6 Grade, Subject, Section ascending table-rank/PK;
7 ContentPage ascending PK then LessonPublication ascending page_id;
8 MediaAsset then Redirect ascending PK;
9 journal row/active pointer.
Never invert when composing operations; a service that would invert restarts at
the outer orchestration boundary. LoginWindow is an independent, short budget
transaction before credential checking and is never held with other locks.
Registration replay may read an unlocked receipt only to identify the candidate
user, then acquires User -> receipt and rechecks every digest/owner fact. New
registration has no existing User lock and inserts user/profile under the scope
lock/unique receipt. Onboarding User -> receipt -> profile. Bulk staff actions
lock sorted users/joins and preflight all PROTECT blockers before mutation.
No filesystem rendering/network/LLM call under DB row locks. Unique constraints
remain the final race defense; nested savepoints handle duplicate inserts,
never continue on an aborted transaction. Deadlock/serialization retries are
bounded and preserve key/body, with safe503 after exhaustion.

Future Assessment/Progress locks are adapter obligations, not implemented tables:
owner/version exposure -> attempt -> permanent action identity -> positive-credit
guard -> Progress user/skill projection in sorted scope. Receipt replay precedes
revision/state checks; immutable event/completion dual identities are global,
not hidden in owner partitions. Assessment emits DTO, Progress alone mutates
projection. The canonical acquisition order must be reviewed again before those
future domains exist; current migration does not implement them.

## Review decisions

at this exact R02 revision. V01 implementation must fill deployment-specific
schema/sequence state; V03 must prove password/session signer compatibility.
