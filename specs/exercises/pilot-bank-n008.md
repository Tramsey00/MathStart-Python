# MS-N008. Пилотный банк Assessment

Банк привязан к существующим темам 6 класса. У каждого задания один основной
навык из графа `pilot-v1`. Связь упражнения с навыком хранится в Assessment
на уровне версии. Две привязки темы к навыку из N007 сохраняет Content.

| Урок | Оцениваемых | Самопроверка | Основные навыки |
| --- | ---: | ---: | --- |
| Положительные и отрицательные числа. Определение координатной прямой | 8 | 1 | Координатная прямая, отрицательные числа |
| Алгебраическая сумма рациональных чисел с разными знаками (`/materials/6-math-15`) | 4 | 0 | Знаки при сложении и вычитании |
| Умножение и деление рациональных чисел (`/materials/6-math-16`) | 4 | 0 | Знаки при умножении и делении |
| Упрощение выражений, раскрытие скобок | 12 | 1 | Распределительное свойство, раскрытие скобок, подобные слагаемые |
| Решение линейных уравнений | 12 | 1 | Сохранение равенства, уравнения в одно действие, уравнения со скобками |

Из 40 оцениваемых заданий 17 с итоговым ответом, 19 пошаговых и 4 структурированных.
У каждого из 10 навыков ровно 4 оцениваемых задания. На навык приходится три
или четыре разных уровня сложности, а банк в целом покрывает уровни 1–4.
Две структурированные формы содержат по два задания. Ученик вводит начальную
координату, перемещение со знаком и конечную координату либо два промежуточных
уравнения и значение неизвестной.

Условия, ключи, решения и допустимые варианты передаются отдельным закрытым
пакетом. Для редакторского просмотра подготовлена сопроводительная версия в
Markdown. Оба файла вне публичного GitHub и без участия в сборке сайта.
Автоматическая проверка квот и форматов не заменяет ручное ревью школьной
математики. Ревью математики и приёмка ожидаются.

## Обновление схемы

Ревизия `v01_0005` добавляет таблицы Assessment, а `v01_0006` запрещает
`TRUNCATE` на этих таблицах. Штатный путь — `backend.release_migrate preview`
с профилем `TARGET_0005` для установленной первой схемы N008 или `TARGET_0004`
для N007, затем `apply --maintenance` с проверенным SHA-256 плана и `check`.
Для новой пустой базы используйте `FRESH`. Проверка схемы сверяет определения
и режим срабатывания триггеров, включая защиту от `TRUNCATE`.
На host-dev используется `scripts/team_local.py schema-preview`,
`schema-apply` и при необходимости `finish-acl` с профилем установленной схемы.
В Compose `dev.cmd schema-update` выбирает профиль из истории установленной
схемы. Действующие правила режима обслуживания, ручного ревью плана и проверки
прав сохраняются.

Локальная runtime-роль читает только таблицы, нужные для выдачи задания.
У оператора банка должна быть отдельная конфигурация PostgreSQL с правами
импорта и блокировок. Возврат приложения возможен с сохранением аддитивной
схемы, если прежняя сборка совместима. Изменение структуры выполняется
следующей миграцией. Не удаляйте строки или таблицы при откате приложения.

## Импорт, публикация и архив

После установки схемы нужны опубликованные уроки и импортированный граф N007.
Храните пакет в закрытом каталоге, например `var/private/ms-n008/`, и передайте
явный путь команде. В Docker предоставьте файл отдельно процессу оператора.

```text
python -m backend.assessment.cli preview --package <private-package>
python -m backend.assessment.cli import --package <private-package> --reviewed-sha256 <sha256>
python -m backend.assessment.cli publish --package <private-package> --reviewed-sha256 <sha256>
python -m backend.assessment.cli archive <exercise-code> <version>
```

- `preview` читает пакет в offline-режиме, проверяет форматы и квоты, печатает
  покрытие и SHA-256 файла. После редакторского ревью используйте именно этот
  SHA-256. `import` создаёт версии в состоянии `DRAFT` одной транзакцией.
- `publish` проверяет сохранённые версии по тому же пакету и публикует их
  одной транзакцией. Повтор идентичной команды сохраняет ID.
  Чтобы заменить задание новым кодом, включите новый код в полный пакет и
  уберите старый из массива `exercises`. В необязательном массиве `archive`
  перечислите точные пары `code` и `version` для каждой версии, уходящей с
  выдачи. Это правило применяется и при замене новым номером под тем же кодом.
  Оператор сверяет список при `preview` и подтверждает SHA-256 всего файла.
  `import` только загружает черновики. `publish` архивирует согласованные
  версии и публикует замену в одной транзакции. Если старая версия уже другая,
  список неполон или одна из новых версий не проходит сверку, весь предыдущий
  опубликованный банк остаётся доступен.
- `archive` снимает конкретную опубликованную версию с выдачи и сохраняет её
  ID, содержание, данные проверки и ссылки на навыки. Тот же номер нельзя
  опубликовать повторно. Используйте эту команду для намеренного снятия
  задания. Для замены целиком используйте список `archive` в пакете.
  Если результат транзакции неизвестен, сверьте состояние в выбранной базе
  перед повтором.
- PostgreSQL блокирует изменения содержания и удаление строк версий, ключей
  и привязок. Публикация требует один основной навык и запись проверки.
  Запуск приложения не импортирует и не публикует банк.

## Закрытый формат checker v2

Полный пакет сохраняет `bank_version: "pilot-v1"`. Обычная строка без
`checker` сериализуется как прежде с `checker_version=1`. Для новой
версии `equation-final-v1` или `equation-steps-v1` используйте отдельное
поле `checker` в строке закрытого пакета.

```json
{
  "version": 2,
  "equation_answer_mode": "TRANSFORMED_EQUATION",
  "initial_state": {
    "schema_version": 1,
    "kind": "EQUATION",
    "parser_profile": "algebra_linear_v1",
    "text": "<исходное уравнение, сверенное с авторским условием>"
  }
}
```

Допустимые режимы пакета — `TRANSFORMED_EQUATION` и `SOLUTION`.
Исходное уравнение обязательно для преобразования и пошагового
решения. Для финального ответа в режиме `SOLUTION` его можно опустить.
Если оно передано, импортёр сверяет корень с исходным уравнением.
Варианты `SOLUTION` должны задавать то же множество решений, что и
ключ. Для преобразования каждый эталон должен быть равносильным
исходному уравнению и показывать проверяемое преобразование. `preview`
проверяет закрытую форму и математическую согласованность до подключения
к БД. Редактор отдельно проверяет соответствие формул условию и
утверждает SHA-256 точного файла. Из текста задания якорь автоматически
не извлекается.

Импорт сохраняет режим и исходную строку в закрытом `validation_spec`,
связанном с immutable `version_id`. Метаданные участвуют в digest
проверки и digest версии. `ExerciseValidation.from_storage` преобразует
уже прочитанную доверенную закрытую запись во вход N011. Публичный
шаблон и привилегии публичного runtime используют прежнюю границу.
Хранение v2 не подключает оценивание к submit N009.

При развёртывании актуального банка на пустой БД сначала примените
подтверждённую историю пакетов с непрерывной нумерацией. Затем примените
полный пакет замен с явным `archive`. Штатный импорт не пропускает
предыдущие номера и не создаёт отсутствующие архивные записи.

## HTTP и версия

`GET /api/v1/topics/{slug}/exercises/` выдаёт страницу опубликованных заданий
из темы активной редакции. Гость видит только `SELF_CHECK`. Для оцениваемой
выдачи используется действующая сессия. Курсор связан с темой, пользователем
или гостевым режимом и размером страницы.

`GET /api/v1/exercises/{id}/` использует стабильный ID упражнения. В DTO
возвращается ID текущей неизменяемой версии. Гость может читать опубликованное
задание `SELF_CHECK`. Оцениваемый или неизвестный UUID даёт одинаковый ответ
401 гостю. Для пользователя с сессией неизвестное или снятое с выдачи
упражнение даёт 404. GET не создаёт попытку и не запускает LLM.
Раскрытие и отправка решения принадлежат следующему этапу Attempt.

Транспорт использует пути, envelope и PublicExerciseDTO R02A. Исключение
для чтения гостевого `SELF_CHECK` следует из решения 16.11.2026.
Замороженные OpenAPI и fixtures сохранены. Схемы ввода сериализуются
из известных версионированных шаблонов. Неизвестная или отличающаяся
схема получает безопасный 503. Запросы не читают таблицу ключей.
